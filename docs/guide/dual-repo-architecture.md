# 双仓架构

## 为什么需要双仓架构？

常见的需求矛盾：
- 想要文档内容开源协作 → 需要公开仓库
- 想要保护主题设计 → 不希望样式代码开源

传统方案只能二选一。双仓架构解决了这个矛盾。

## 架构原理

```
┌─────────────────────────────────────────────────────┐
│                   公开仓库 (Public)                  │
│  github.com/hpp-bot/vite-docs                       │
│  ├─ docs/           ← 所有人的协作内容              │
│  ├─ .vitepress/theme/  ← 空壳（由CI填充）           │
│  └─ .github/workflows/  ← CI/CD 定义               │
└─────────────────────────────────────────────────────┘
                          ↓ git pull (CI中)
┌─────────────────────────────────────────────────────┐
│                  私有仓库 (Private)                   │
│  github.com/hpp-bot/vite-docs-theme                 │
│  └─ .vitepress/theme/  ← 主题样式，仅作者可访问     │
└─────────────────────────────────────────────────────┘
                          ↓ vitepress build
┌─────────────────────────────────────────────────────┐
│                 GitHub Pages (公开访问)              │
│  hpp-bot.github.io/vite-docs/                      │
└─────────────────────────────────────────────────────┘
```

## 两个仓库的职责划分

| 职责 | 公开仓库 | 私有仓库 |
|------|---------|---------|
| Markdown 文档内容 | ✅ | ❌ |
| 前端 UI 框架代码 | ✅ | ❌ |
| CI/CD 配置 | ✅ | ❌ |
| CSS 主题样式 | ❌ | ✅ |
| 自定义 Vue 组件 | ❌ | ✅ |
| Git 访问权限 | 所有人 | 仅作者 |
| GitHub Pages 部署 | ✅ 构建来源 | ❌ |

## 同步机制

使用 GitHub Actions 实现自动同步：

1. 当私有仓库推送新主题时，触发 `sync-theme.yml` workflow
2. Workflow 使用 PAT clone 私有仓库
3. 将 `.vitepress/theme/` 复制到公开仓库对应位置
4. 提交并推送到公开仓库
5. 公开仓库的 `deploy.yml` 捕获推送事件
6. 执行 `vitepress build` 构建并部署到 GitHub Pages

## 安全性考量

- PAT 存储在公开仓库的 GitHub Secrets 中，只有 Actions 可以访问
- 私有仓库的权限设置为 minimum required（repo scope）
- 公开仓库中的 `.gitignore` 不包含敏感信息

## 局限性

- 主题变更需要约 1-2 分钟才能反映到线上
- 需要维护两个仓库的同步状态
- 首次部署需要手动触发一次 workflow
